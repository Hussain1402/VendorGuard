    Security controls

    Tick a control to apply it. Each control lowers the likelihood or impact of the threats it addresses by one level.

    ThreatMITRELikelihoodImpactInherent riskResidual riskMissing controls

    Risk = Likelihood × Impact on a 1–4 scale (Low, Medium, High, Very High). Score 8–16 Critical, 5–7 High, 3–4 Medium, 1–2 Low. Inherent ratings reproduce the risk-assessment table in the report.

    What this tool does

    VendorGuard turns the case study's methodology into something you can run. It reads a bank's third-party access log, checks every event against each vendor's access policy, and flags the behaviour the report says must be monitored.

    Using your own data

    Click Load log file… and pick a CSV with these columns:

    timestamp,vendor_id,account,src_ip,country,action,target,zone,mfa,role,bytes_out,files_modified,result

    Actions: login, logout, privilege_change, account_enum, port_scan, remote_session, file_access, data_transfer, file_modify. You can also pick a vendors.json policy file in the same dialog.

    About the data

    The built-in log is synthetic. It describes a fictional bank and fictional vendors, and includes one simulated vendor-account compromise so every rule can be demonstrated.

    It does not describe ICICI Bank's systems. As the report explains, the January 2025 Bashe claim was not substantiated, and ICICI Bank reported no material cyber incident.
